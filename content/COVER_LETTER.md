# Cover Letter — Game Developer Assessment Author

Dear Hiring Team,

I am applying for the role building game-engine assessment projects, gameplay bugs, feature challenges, reference solutions, and testable success criteria. I am a game developer and systems designer who works by making a design question playable, reproducing the result, and turning evidence into a precise revision.

My solo Unity 6/C# project, Alcherogue, is the clearest example. I built its interconnected pouring, potion-quality, stock, haggling, auction, and rent systems, then made runs reproducible through seeded randomness. I also created developer tools for state jumps, screenshots, playtest logs, and build tracking, and checked the interface across iPhone, iPhone SE, and iPad aspect ratios. Those tools let me reach a known state quickly, observe the outcome, and verify a change rather than relying on memory.

I use small tests to find problems that are easy to miss on paper. A Python script proved that an earlier four-jar deduction design was always solvable in exactly two pours with one fixed strategy, so I cut it. Further simulations exposed economy issues and a perceptual problem: one recipe provided only 2.8 degrees of visible hue change. I then ran a 15-person paper playtest of the replacement core loop. It showed that container shape changed the fairness of the same pouring task, leading me to limit container varieties and design measuring aids players could buy.

The same observation-to-fix loop appears across my team work. In Fih Together, a three-person test questioned why players needed a shared virtual Pond, so I designed joinable sessions where larger groups improve the chance of better fish. In (Not) Very Disco, prototype feedback asked for stronger impacts, so I redrew and retimed animations and added hit stop. In Nimbus Harvest, I replaced automatic harvesting with direct input, animation, sound, and coin feedback to make the action readable and satisfying.

This background maps closely to your assessment workflow: I can build compact Unity scenes, combine several gameplay systems, create reproducible states, document the intended behaviour, implement and verify fixes, and playtest the full path. My completed AI-evaluation contract also required me to follow detailed technical guidelines, interpret API and tool behaviour, and write clear English judgements. Although this would be my first dedicated game-assessment author role, the core work—technical design, controlled testing, precise documentation, and evidence-based debugging—is already central to how I develop games.
